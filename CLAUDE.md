# nexus-python-clients

Python clients of the nexus services, generated by openapi-generator from each service's committed API spec. Nothing in a part is written by hand: a change goes into the service's API, then the part is generated again.

| Part | Service | Package |
|---|---|---|
| `aigentchat/` | aigentchat | `aigentchat` |
| `core/` | vaud-ai-core | `core` |
| `filemanager/` | vaud-ai-file-manager | `filemanager` |

Each part is a package of its own. Its version is stamped in `pyproject.toml`, `setup.py` and `<package>/__init__.py`.

## Generating a part

```sh
./generateClient.sh <part> <spec file> <version>
```

- **The spec** is the service's `docs/swagger.json`, at the service's release tag `v<version>`.
- **What it does:** it replaces `<part>/` with the client generated from the spec, stamped with `<version>` (`X.Y.Z`, without the `v`).
- **What it never does:** commit, tag or push.
- **The generator:** it needs openapi-generator 7.23.0, which every part was generated with, and refuses another version.
- **By hand:** `./generate{AigentChat,Core,FileManager}Client.sh <tag>` takes the spec at the service's tag through `gh`.

A generation that changes nothing but the stamped version changes no API: in a vaudy client thread, that ends without a PR.

## Checks

`./check.sh` installs each part into a fresh virtualenv, imports it, and runs its tests.

## Releases

A person tags the merge commit of the PR that generated a part `<part>/v<version>`, with the service's version. There's no release PR. Consumers pin the tag:

```
<package> @ git+https://github.com/vAudience/nexus-python-clients.git@<part>/v<version>#subdirectory=<part>
```
